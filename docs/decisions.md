# Arxitektura qarorlari jurnali

Format: sana — qaror. Sabab. Yangi qarorlar oxiriga qo'shiladi; eski qaror o'zgarsa, yangisida qaysi biri bekor qilinganini yoz.

- **2026-10-01 — Tekshiruv faqat serverda.** O'quvchi kompyuterida faqat ochiq testlar ishlatiladi (starter orqali), rasmiy verdict faqat serverdan. Sabab: mijoz qurilmasiga ishonib bo'lmaydi — natijani soxtalashtirish va yashirin testlarni o'qish oson.
- **2026-10-01 — Kutubxonalar topshiriq image'iga bir marta o'rnatiladi.** O'quvchi kutubxona qo'sha olmaydi. Sabab: har yechim uchun `pub get` sekin; tekshiruv internetsiz ishlaydi.
- **2026-10-01 — Stack: Django monolit + HTMX + PostgreSQL navbat.** Sabab: auth, admin, ORM tayyor; Redis/Celery'siz kamroq servis; sahifalar zaif kompyuterlarda ham yengil.
- **2026-10-01 — Tayyor judge tizimlari (Judge0, DMOJ va h.k.) ishlatilmaydi.** Sabab: ular stdin/stdout dasturlari uchun; loyiha darajasidagi test freymvorklari, kutubxonalar va test-ma-test jonli natija uchun mos emas.
- **2026-10-01 — Judge yadrosi tilni bilmaydi, tilga oid hamma narsa runner profilda.** Sabab: Flutter, Dart, backend va frontend bitta yadro bilan; yangi til yadroga tegmasdan qo'shiladi.
- **2026-10-01 — Backend qora quti usulida tekshiriladi.** O'quvchi serveri va testlar alohida konteynerlarda, umumiy network namespace orqali. Sabab: testlar o'quvchi tiliga bog'liq emas; o'quvchi kodi test jarayoniga tegolmaydi.
- **2026-10-01 — Flutter tezligi: birlashtirilgan test fayli, isitilgan kesh, ikki bosqich (`dart test` → `flutter test`).** Sabab: asosiy vaqt kompilyatsiyaga ketadi; mantiq xatolari og'ir widget kompilyatsiyasisiz aniqlanadi. Ikki bosqich PoC natijasiga bog'liq.
- **2026-10-01 — Server: Oracle Always Free A1, linux/arm64, 2 OCPU / 12 GB.** Boshida 1 `heavy` + 1 `fast` slot. Parallel tekshiruvlar soni faqat `JUDGE_SLOTS` va qo'shimcha worker nodelar bilan oshiriladi.
- **2026-10-01 — UI konsepsiyasi "Uy vazifasi daftari".** Katakli daftar, qizil hoshiya, o'qituvchi belgilari va muhr; jurnal acmp uslubida. Tafsilotlar: `docs/UI.md`.
- **2026-10-01 — `judge` qatlamlari orasidagi bog'liqlik testi.** `tests/test_architecture.py` importlarni AST orqali tekshiradi: `core` judge'ning boshqa qismlariga bog'liq emas; `parsers` va `packaging` faqat `core` ni ishlatadi; Docker faqat `infra` da, Django faqat `adapters` da; `cli` Django'siz ishlaydi. Use-case'ga parser yoki validator kerak bo'lsa, u parametr sifatida beriladi. Sabab: "bog'liqliklar ichkariga qaraydi" qoidasini code review emas, `make check` ushlab tursin.
- **2026-10-01 — Testlar repo ildizidagi `tests/` da, `--import-mode=importlib`.** Tuzilma kod papkalarini takrorlaydi (`tests/judge/parsers/...`); parser fixture'lari `tests/**/fixtures/` da va pre-commit ularga tegmaydi. uv loyihasi paket sifatida o'rnatilmaydi (`package = false`), kod repo ildizidan ishlaydi. Sabab: judge va Django ilovalari testlari bitta joyda, bitta `pytest` bilan.
- **2026-10-01 — Event oqimi qat'iy tartibda tekshiriladi.** `index` — testning manifestdagi 1 dan boshlanadigan tartib raqami. Yagona to'g'ri oqim: har test uchun `start`, keyin `pass`/`fail`; bosqichning oxirgi testidan keyin o'sha bosqichning `done` i. Birinchi `fail` dan keyingi eventlar e'tiborsiz qoldiriladi (konteyner o'ldiriladi). Boshqa har qanday holat, jumladan oxirgi `done` dan keyingi event, `runtime_error`. `done` kelmasa `accepted` berilmaydi. Sabab: SPEC §3.7, soxtalashtirishga qarshi; shubhali oqim hech qachon qabul qilinmaydi.
- **2026-10-01 — Kompilyatsiya xatosi event emas, `RunOutcome.compile_error`.** SPEC §3.5 dagi 4 ta event turi (`start`, `pass`, `fail`, `done`) o'zgarmaydi; parser yuklash/kompilyatsiya xatosini alohida qaytaradi. Aniq interfeys `dart_json` parser vazifasida, haqiqiy chiqishlar asosida belgilanadi.
- **2026-10-01 — `judge/core` UI matni qaytarmaydi.** Verdict yorliqlari ("N-testda xato" va h.k.) UI qatlamida (`docs/UI.md` §9). `Judgement.detail` faqat o'qituvchi logi uchun texnik izoh (inglizcha, xom dart/docker chiqishi kabi). Sabab: core Django'siz, i18n (rus tili, Phase 4) esa UI qatlamida bo'ladi.
- **2026-10-01 — `dart_json`: sintetik testlar shakli bo'yicha aniqlanadi, `hidden` belgisi bo'yicha emas.** Haqiqiy chiqishda (Dart 3.13.5, test 1.32.0) xato bergan "loading …", `(setUpAll)`, `(tearDownAll)` testlari `hidden: false` bilan keladi, `testStart` da esa bu belgi umuman yo'q. Shuning uchun guruhsiz test — yuklash (xatosi `compile_error`), "guruh nomi + (setUpAll)/(tearDownAll)" — hook. Sabab: belgiga ishonilsa, yashirin hook xatosi oddiy test bo'lib ko'rinadi.
- **2026-10-01 — `dart_json`: `done` faqat dart `success: true` desa chiqariladi.** Hook xatosi yoki test tugagandan keyingi xato oqimni to'liq bo'lmagan holda qoldiradi, natija `runtime_error`. O'tkazib yuborilgan (`skipped`) test `fail` hisoblanadi: o'qituvchi testlarida `skip` ishlatilmaydi. JSON bo'lmagan qatorlar logga yoziladi va e'tiborsiz qoldiriladi; ular hech qachon `accepted` ga olib kelolmaydi, chunki `RunProgress` aniq oqim talab qiladi. Sabab: shubhali natija qabul qilinmaydi.
- **2026-10-01 — O'quvchi kodi faqat pubspec `dependencies` dagi paketlarni import qiladi.** `dev_dependencies` (`test`, `flutter_test`, `mocktail` …) taqiqlanadi; SPEC §3.4-2 shunga moslandi. Sabab: Dart `lib/` dan dev paketlarni import qilishga ruxsat beradi; o'quvchi `package:test` orqali, masalan, `markTestSkipped` chaqirib, test natijasiga ta'sir qilishi mumkin. Erkin tasdiqladi.
- **2026-10-01 — Zip diskka ochilmaydi.** `judge/packaging/zip_validator.py` avval hamma yozuvlarning metama'lumotini tekshiradi (`validate_zip`), keyin faqat tanlangan fayllarni limit ichida xotiraga o'qiydi (`ValidatedZip.read`). Ular konteynerga tar orqali beriladi. Sabab: diskka yozilmasa zip-slip va symlink hujumi uchun joy qolmaydi.
- **2026-10-01 — Zip tekshiruv qoidalari.** Butun zip rad etiladi, agar unda: xavfli yo'l (`..`, absolyut, `C:`, boshqaruv belgilari), symlink yoki boshqa maxsus fayl, parol, qo'llab-quvvatlanmaydigan siqish, bir xil nomli fayllar yoki bir yo'l ham fayl, ham papka bo'lsa. `\` ajratgich `/` ga aylantiriladi (Windows PowerShell shunday zip yaratadi). Hajm va fayllar soni limiti faqat o'qiladigan fayllarga qo'llanadi, shuning uchun butun loyihani zip qilgan o'quvchining `build/` papkasi sababli zip rad etilmaydi. Xabarlar o'zbekcha (`UI.md` §8), yonida `ZipProblem` kodi bor, i18n uchun.
- **2026-10-01 — Symlink bor zip butunlay rad etiladi (SPEC bo'yicha), keraksiz papkalarda bo'lsa ham.** O'quvchi aniq xabar oladi va faqat `lib/` ni qayta yuklaydi. Erkin tasdiqladi.
- **2026-10-01 — Yangi sozlamalar: `SUBMISSION_MAX_UNPACKED_MB=20`, `SUBMISSION_MAX_FILES=500`, `TASK_MAX_UNPACKED_MB=200`, `TASK_MAX_FILES=5000`.** Zip validatorining ochilgandagi hajm va fayllar soni limitlari; SPEC §6 ga qo'shildi. Erkin tasdiqladi.
- **2026-10-01 — SDK versiyalari qat'iy: `FLUTTER_VERSION=3.47.5` (2026-09-18 dagi stable, ichida Dart 3.13.4), `DART_VERSION=3.13.5`.** `DART_VERSION` yangi kalit: dart base image ham Flutter kabi aniq versiyaga bog'lanadi. Sabab: bir xil yechim har serverda va har yig'ishda bir xil natija bersin.
- **2026-10-01 — Base image teglari: `ohw-base-dart:<DART_VERSION>`, `ohw-base-flutter:<FLUTTER_VERSION>`.** `scripts/build-base-images.sh` (`make base-images`) versiyani `.env` dan oladi, image'ni joriy arxitekturada yig'adi va tekshiruv sharoitida (`--network none`, uid 1000) isitish testini qayta ishga tushiradi. SDK va pub keshi uid 1000 ga tegishli: Flutter tool o'z keshiga lock va stamp fayllar yozadi. Tag'dan `git clone` qilingani uchun `flutter --version` kanalni `[user-branch]` deb ko'rsatadi — bu normal.
- **2026-10-01 — Flutter base image `debian:trixie-slim` (Debian 13), bookworm emas.** SPEC §4 moslandi. Sabab: bookworm endi oldstable, rasmiy Dart image ham trixie'da; apt'dan keyingi qadamlar sessiya muhitida trixie ustida tekshirildi. Erkin tasdiqladi.
- **2026-10-01 — `test/hidden/` majburiy (SPEC'dagi namuna bo'yicha).** Paketda yashirin test bo'lmasa, yig'ish o'qituvchiga aniq xato bilan to'xtaydi.
- **2026-10-01 — Image builder Dockerfile'siz: sandbox konteyner + `commit`.** 1) Base image'da `pub get` — internet faqat shu qadamda. 2) Isitish: o'qituvchi yechimi bilan testlar xuddi tekshiruvdagidek (internetsiz, o'sha limitlar) ishlaydi, hamma test o'tishi shart; yechim (`lib/`) o'sha konteynerning ichida o'chiriladi, shuning uchun image qatlamiga tushmaydi, kompilyatsiya keshi esa qoladi. Sabab: Docker SDK BuildKit'ni (`RUN --network=none`) qo'llamaydi; konteyner yo'li isitishni tekshiruv bilan bir xil sharoitda o'tkazadi.
